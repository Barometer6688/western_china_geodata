# 原始地理表格的八项编制规则（用户2026-11-03说明，经结构化整理）

这是对用户亲自说明的规则的结构化转述，不声称为用户逐字原文；原始工作簿中的具体备注优先于概括文字。

1. **城区中心海拔的取点**：主要为DEM观测值。优先以县级政府驻地为代表点；当政府驻地偏僻、距实际城区中心较远时，改选更热闹、具有代表性的地标。故该值不是全县平均海拔、整个县城建成区的平均海拔，也不必是几何中心。
2. **行政边界和共享极值**：行政边界受底图分辨率限制；距界约200米至2公里以内的地形极值，可允许相邻两侧县域同时计入，容忍距离依据边界资料分辨率而定。共享最高点无需严格坐落在县界线上。
3. **星号、误差与来源冲突**：带 `*` 的记录在现有资料下无法继续精确，除非实地测量；海拔及少量经纬度也可能存在误差。多个来源冲突时选相对可信来源，其他候选信息写在备注。不能抹掉 `*` 或将估算伪装为精确实测。
4. **水域与最低点取值**：水域最低点没有统一适用的简单规则；河流、水库等通常参考水体流出县域的位置。不能一律把水面最低值当河床高程或固定水位；按照表格实际备注解释。
5. **连续建成区与排名单元**：根据卫星影像判断连续建成区，将实质相连城区合并为一个排名单元；行政上分开的区县仍可保留原记录，并用备注解释拆分、归并与排名口径。统计‘县级行政区数量’和‘独立城区排名单元’须分开。
6. **地名及本地称呼**：倾向采用更本地化的地名；与其他称谓或译名冲突时，在备注记录对应关系。用户问常见名称时可建立匹配，但应保留表中原称。
7. **特殊记号与代码**：方括号 `[]` 代表面积；部分看似孤立的数字是行政区划代码，不应当当作海拔、坐标或计数。具体单位、代码、格式仍以原工作表的表头和备注为准。
8. **时间截面**：行政区划以**2025年9月**为截至点；仅在出现重大变化时更新数据。这意味着本Skill提供的是该版本体系下的静态记录，不代表实时区划现状。
